# 研究方案

## 先定义“原汁原味”

本研究把目标分为三层，避免用一个模糊的相似度承诺覆盖所有问题。

| 层级 | 要证明什么 | 需要的证据 |
|---|---|---|
| A：原厂 LUT 忠实执行 | 对相同且满足规范的输入，忠实执行原厂变换 | 固定 LUT 文件、输入输出色彩规范、独立渲染器比较 |
| B：富士原机外观匹配 | 尼康拍到的场景经适配后接近指定富士相机的输出 | 同场景两机样本、固定参数、多种光线、留出场景 |
| C：尼康机内近似 | 在 NP3 参数约束内接近 A/B 的参考结果 | NX Studio 输出、实际 Z6III JPEG、残差与视觉评估 |

A 可先独立研究；B 需要真实富士参考，只有 LUT 不能证明；C 可能受机内表达能力限制。颗粒、降噪、锐化、局部处理等空间效果不由单纯逐像素颜色 LUT 完整描述。

## 三条路线与选择

| 路线 | 好处 | 局限 | 本次决定 |
|---|---|---|---|
| 官方 LUT + 明确的颜色输入适配 | 原厂变换可追溯，易做数值对照 | 仍需处理尼康输入差异；先在电脑运行 | 主线，先做 |
| 用尼康灵活颜色/NP3 拟合参考输出 | 能研究照片直出、取景预览 | 参数空间有限，可能无法覆盖完整 3D 颜色映射 | 第二阶段 |
| REA 辅助研究桌面处理程序或相机固件 | 能回答源码之外的具体实现问题 | 工具与证据成本高；解包不等于能运行补丁 | 桌面问题按需；固件暂作远期课题 |

不能因为 REA 能反编译，就推断它能识别、移植富士图像处理器代码。初期不需要逆向富士固件，官方 LUT 已提供一个可测量的色彩目标。

## 第一阶段：冻结原厂参考

1. 从富士官网取得 GFX ETERNA 55 当前 LUT ZIP；记录网页版本、压缩包文件名、取得时间、SHA-256、压缩包内文档。
2. 盘点 F-Log2 / F-Log2C、网格规格、模拟名称、DOMAIN、数据顺序和输出编码。以实际包内文档为准，不凭名称推定。
3. 当前网页显示 1.10，第三方 Fujifilm-LUTs 声明使用 1.00。先比较目录、技术文档和关键变换，不直接套用旧脚本路径。
4. 建立灰阶、RGB 立方体采样、肤色/叶绿/天空重点颜色测试。检查域外值、负值、截断与插值。
5. 用两个独立实现比较同一输入（例如自建 CPU 采样器与可验证配置的成熟调色软件）。先验证身份 LUT、通道顺序和色阶，再验证真实 LUT。

产物：文件清单、原始文件哈希、颜色契约、测试图、数值差异表。此阶段不宣称富士相机 JPEG 复刻。

## 第二阶段：尼康输入适配

照片和视频必须独立建链，不能共用一个不说明输入的“万能 LUT”。

- 照片：NEF → 固定 RAW 解码器/相机输入配置 → 白平衡与曝光基准 → 明确的场景参照颜色空间 → 原厂 LUT 所需输入 → 官方 LUT → 明确的显示输出。
- 视频：Z6III N-Log/实际记录色域 → 已核实的解码与颜色变换 → 官方 LUT 输入 → 官方 LUT → 输出编码。
- 不把相机标准 JPEG 直接当 F-Log2，也不先做不明 Rec.709 显示渲染再假装能无损倒回场景数据。
- 第三方脚本的曝光补偿、逆曲线、色适应与矩阵均作为待检验假设。先读代码，再建立自己的基准；未经本地复现不标为通过。
- 传感器光谱响应的差异不能靠普通色域矩阵保证消除。灰卡/色卡可以帮助校准，但不代表全部实景都匹配。

五款目标已确定为 Classic Neg、Nostalgic Neg、Classic Chrome、理光 GR III Positive Film、Negative Film。先以官方包内确有的 CC/NC 做数学参考；另外三款另建目标样本，不能套用 CC/NC 的证据。

## 第三阶段：机内 NP3 拟合

1. 用尼康 NX Studio 创建/导出中性基准和单参数变化的 NP3，每次只改变一个变量，记录软件版本。
2. 先尝试官方编辑器可表达的参数，不以未知二进制字段为起点。社区解析器可辅助阅读，不默认其模型正确。
3. 用同一组 NEF 固定其他参数，针对参考结果拟合色彩混合器、分级和曲线。使用训练/留出场景，禁止同一场景近似照片分在两边。
4. 通过 NX Studio 重新导入、导出、读取参数与视觉比对，再用用户 Z6III 的官方菜单导入进行实际拍摄。
5. 输出每个场景的残差、肤色和高饱和色问题。若机内能力不足，保留电脑端完整颜色方案，机内只标注近似。

机内基准不等于电脑参考：必须记录“标准/自然/灵活颜色”等具体起点、色调模式、白平衡、动态 D-Lighting 和曝光。

## 第四阶段：有问题才引入 REA

优先回答 NX Studio 的 NP3 读取/写入、曲线插值或某个参数如何影响结果等边界清晰的问题。先取得版本固定的软件文件和输入/输出样本；记录哈希、函数位置、操作步骤、实测行为以及反编译推断。

固件路线另行评估：先有 Z6III 精确版本的可验证解包、架构和代码定位证据，再讨论移植可行性；本方案没有刷机步骤。Z8 的成功不能作为 Z6III 兼容证据。

## 决策门槛与停止条件

- G0：资料版本和颜色契约完整，才能渲染；缺少任一输入编码说明则不出“准确”结论。
- G1：独立渲染器数值一致后，才能比较第三方转换。浮点基准可预设归一化最大绝对误差 1e-5；这只是工程目标，跨网格/位深需另列误差预算。
- G2：真实素材上检查中灰、色偏、过曝、渐变及肤色，不以单图好看作为通过。
- G3：只有 NX Studio 和真机回读均通过才标注“Z6III 机内验证”。
- G4：达不到 NP3 的可接受效果时，记录具体失败场景，不强行继续增加未知字段。
- 需要精确匹配某台富士相机时，先补该型号及设置的对照素材；没有实物参考就保留为未验证。

本文件为研究设计；官方 CC/NC LUT 数值盘点已经开始，RAW 输入适配和实拍验收尚未完成。
