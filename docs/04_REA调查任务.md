# REA 的位置和准备

默认来源：[REA 官网](https://rea.tools/)及官网链接的 [morluto/rea](https://github.com/morluto/rea)。ERA 是另一个建立在 REA 上的项目，不是本阶段必需。

REA 提供调查工具和证据入口，不保证恢复完整源代码、找到成像算法或完成跨处理器移植。官方仓库列有实验性的 Windows Ghidra 支持；本机兼容性尚未验证。

## 安装准备状态

本机 PATH 已有 `rea.cmd`，启动脚本指向本地 `rea-agents/scripts/rea.mjs`；包元数据为 `rea-agents 6.4.0`，repository 指向 `morluto/rea`。这只能证明已有本地包及其声明来源，不等于完整性、MCP 注册或分析后端已验证。

本次只查环境和拟定任务，没有执行 `npx rea-agents setup`。先检查现有安装再决定是否更新；需要安装时从官方源核实当时稳定版本，固定版本、查看安装计划，记录 MCP/客户端配置将改动的文件，并按安装器要求完成确认和重启。Ghidra/Java 的具体版本要求以该固定版文档为准，不提前猜测。

这是工具安装流程的准备记录，不是当前研究目录创建的阻断项。工具不影响先开展官方 LUT 实验。

## 第一项建议调查：NP3 曲线和参数

问题：NX Studio 导出 NP3 的某个单参数变化，对写入字段和输出画面的影响是什么？

输入：合法取得的本机 NX Studio、确切版本和文件哈希；中性 NP3、仅改变一个参数的 NP3、同一 NEF 与固定设置的输出。

步骤：先比较文件与可见行为；若社区解析和实测不一致，再用 REA 检查相应读写函数、数据引用和插值路径。优先静态分析。需要运行目标时明确输入输出目录及行为。

交付：字段偏移/类型/范围假设、函数地址/引用、控制变量样本、官方软件回读结果。区分：原始数据、反编译推断、行为确认。

## 第二项可选调查：第三方颜色链

若公开 Python 源码已可阅读，直接审查源码即可，不需要 REA。重点查旧版本 LUT 路径、曝光偏置、逆曲线和颜色空间假设；用合成色块证伪。只有闭源依赖造成明确障碍时才考虑原生分析。

## 固件研究的进入条件

必须先拥有用户 Z6III 的实际固件版本、同型号官方固件原始包及哈希、明确可复现的解包证据，以及无法通过 NP3/电脑流程解决的具体目标。目前这些条件未满足。当前文档不提供写入相机的方法，也不把“未来可能”写为支持。
